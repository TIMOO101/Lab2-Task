# Lab2-Task
Since version control is an essential skill for any software developer, this week’s task is all about getting hands-on with Git and GitHub! You have one week to complete this assignment.

Task Requirements (Step-by-Step):

Create an Account: Sign up for a personal account on GitHub (if you don't already have one).

Create a Public Repository: Create a new repo and make sure it is set to Public. You can name it something like  Lab2-Task.

Initialize with a README: Add a README.md file and write a brief introduction about yourself or what this task is about.

Apply Branching: Create a new branch from main (for example, name it feature/update-readme).

Make a Commit: Inside your new branch, make a change (edit the README or add a new simple file). Save your changes with a clear and meaningful commit message.

Open a Pull Request (PR): Push your changes and open a Pull Request to merge your new branch into the main branch.

Merge the PR: Finally, merge your own Pull Request so that the main branch is updated with your new code.

 Why are we doing this? (A Quick Example): Imagine you are working on a project with a team. The main branch is the stable, final version of your project. If you want to add a "new feature", you don't edit the main code directly. Instead, you create a side branch, add your code, and ask your team to review it via a Pull Request. Once approved, your code is merged into the main project. This is exactly the workflow you are practicing today!
